# FastAPI client integration

## Configuration and transport

`app.config.ts` provides Angular HttpClient with two functional interceptors: error normalization wraps the session interceptor, so authentication handling sees the original server status before consumers receive a normalized error. `API_BASE_URL` defaults to the build environment's `/api/v1`. All feature requests use `core/api/ApiService`; authentication keeps its existing dedicated service and skip-redirect context, using the same URL builder and interceptors.

For local development, `npm start` uses `proxy.conf.json` to forward `/api/**` to `http://localhost:8000`, preserving the browser Origin for backend CSRF verification. Production should route `/api` to FastAPI on the frontend origin. For a separate backend origin, set the existing production `environment.apiBaseUrl` to an explicit URL such as `https://api.example.com/api/v1` before building, or override the `API_BASE_URL` provider in deployment-specific application configuration. Config contains no secrets. An operator must provision the backend's existing exact CORS/Origin allowlist and compatible cookie settings; frontend changes cannot bypass browser cookie policies. Never place credentials in a URL.

The URL helper requires HTTP(S), the existing `/api/v1` version suffix and no userinfo/query/fragment in configuration. Endpoint paths cannot supply their own origin, escape the API prefix or use encoded path separators/traversal. Trust compares exact scheme, host, port and path-segment boundaries. Credentials and `X-CSRF-Protection: 1` are added only inside that configured boundary; safe GET/HEAD/OPTIONS receive no write header. Unrelated HttpClient traffic is untouched. HttpOnly cookie contents are never read, logged or stored in browser storage. There is no JWT or alternate CSRF mechanism.

Feature services keep business endpoints and typed inputs/responses near their features. UI components do not perform HTTP requests. The transport passes through pagination headers, blobs and cancellation. It does not retry or cache requests automatically.

## OpenAPI source and regeneration

`openapi/atelier-api.json` is a schema-only snapshot exported from the existing backend commit `3495621f880b666c0e716bf00b63995c1a44e0aa`. No backend files or contracts were modified. `core/api/generated/schema.ts` contains generated OpenAPI components, paths and operations; **do not edit or format this generated file manually**.

Install and verify:

```sh
npm ci
npm run api:setup
npm run api:generate
npm run api:check
```

`api:setup` uses the independent lockfile in `tools/openapi/`. `openapi-typescript` 7.13.0 declares a TypeScript 5 peer; isolating its pinned TypeScript 5.9.3 avoids overriding Angular's TypeScript 6 peer requirements. These tools are development-only and are not shipped in the application. No force/legacy peer resolution is required.

To deliberately refresh or compare with a backend checkout whose `.venv` is installed:

```sh
npm run api:snapshot -- --backend ../atelier-api --check
npm run api:snapshot -- --backend ../atelier-api
npm run api:generate
npm run api:check
```

The exporter imports `app.openapi()` with an import-only SQLite URL and no bytecode writes. It does not start the application, connect a database, run migrations, invoke endpoints or modify backend sources. It ignores the backend's configured database URL. Review snapshot and generated diffs together; update the documented/pinned backend commit deliberately. Snapshot exports contain schema metadata only, never live customer/account records or tokens.

Entity and request aliases derive from generated schemas. Existing editors deliberately provide all editable values, while read adapters require fields the current FastAPI serializers include as defaults/nulls. UI pagination wrappers and load state remain frontend types. OpenAPI types are compile-time contracts, not runtime payload validation. Explicit null versus omitted PATCH fields retain their existing meaning.

Frontend CI installs the isolated tooling and compares generated bytes against the committed snapshot. Type checking/build catches incompatible field/type changes used by consumers. Browser CI additionally exports the explicitly pinned backend schema and compares it with the snapshot. This detects drift in the checked contract, including paths; it does not poll arbitrary deployed services or automatically accept newer backend contracts.

## Errors, session handling and forms

`ApiError` extends `HttpErrorResponse` for compatibility with existing status consumers and adds `kind`, German `userMessage` and sanitized validation locations. It covers network failures, 400/401/403/404/409/422/429/5xx and unknown errors. Raw FastAPI `msg`, `input`, `ctx`, tracebacks and response bodies are discarded. Feature error helpers provide contextual not-found/conflict text without repeating status switches. There are no global error toasts: the owning screen displays one inline error.

A protected request's 401 clears only the matching session revision and triggers the existing deduplicated login navigation. Auth endpoints and explicit skip contexts do not redirect. Role-related 403 keeps the session and navigates to access denied. The existing backend uses `Request forbidden` for rejected Origin/CSRF headers and `HTTPS required` for transport rejection; these exact 403 details stay inline as a security-check error and preserve the editor. There is no invented CSRF status code. If the backend changes these details, update the contract tests deliberately.

`applyApiValidation` maps only direct `['body', field]` validation locations to existing enabled controls using a generic German message. It preserves other control errors, marks controls touched, and ignores unknown/prototype/query/nested/model locations. The form-level alert remains for unmapped or non-field failures. It never resets input. Editing a value re-runs normal validators and clears its stale server error, allowing correction and retry. Pending guards prevent duplicate submissions; controls retain their existing accessible field-error associations.

`ApiLoadState<T>` shares loading/loaded/error semantics. Empty collections are loaded data, never fabricated successes after failures. Existing Signals hold screen state; RxJS switchMap/debounce cancels superseded searches and route loads, and takeUntilDestroyed cleans up subscriptions. Existing mutation cancellation on route changes and session revision checks prevent late responses from overwriting newer state. No global state library was introduced.

## Verification

Unit tests use Angular HTTP testing to verify trusted and lookalike origins/ports/paths, configuration validation, JSON/blob/metadata transport, unsubscribe cancellation, status normalization, secret-free error bodies, CSRF/session behavior and safe field mapping/correction. Existing feature tests cover preserved values, pending submissions, stale responses and navigation cancellation. Browser suites exercise the production bundle against the real FastAPI service, plus explicitly mocked error scenarios including inline CSRF rejection.

Remote GitHub Actions status is established only after pushing. No backend aggregation, signing endpoint, authorization rule or storage capability was added by this frontend issue.

## CI metadata comparison

The backend software release (`info.version`) derives from installed VCS package metadata. A shallow GitHub checkout can report `0.1.dev1+g3495621f8` for the same source that reports `0.20.0` in a tagged local checkout. The snapshot contract comparison excludes only this field and compares JSON objects independently of key order. All paths, operations, schemas, required fields, authentication definitions and the OpenAPI specification version remain checked. The committed snapshot and generated types are not rewritten or weakened. `npm run test:api-tooling` tests both the observed CI mismatch and rejection of real contract changes; both workflows run it before checking contracts.
